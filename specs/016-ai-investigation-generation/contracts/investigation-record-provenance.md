# Contract: Investigation Record Provenance

**Feature**: `016-ai-investigation-generation`
**Scope**: Local investigation files, projection fields, lifecycle/review compatibility, and UI
provenance display

## Persisted Files

A generated Feature 016 investigation directory contains:

```text
<selected-shift>/investigations/<normalized-name>/
├── investigation.md
├── generation-status.json
├── evidence-provenance.json
└── reviewed-context.json
```

Existing legacy records may contain their legacy files (for example `noc-inv.log` or
`evidence/copilot-notebook-summary.md`). Those records remain readable and reviewable.

## investigation.md

The existing metadata and required sections are preserved:

```markdown
# Investigation: Checkout Latency
- Display Title: Checkout Latency
- Investigation Name: checkout-latency
- Shift Date: 2026-11-10
- FINAL Datadog Notebook: https://app.datadoghq.com/notebook/16295624/runbook
- Evidence Provenance: ai-evidence
- Evidence Status: PARTIAL
- Evidence References: incident:aadf... , notebook:16295624 , monitor:150243517

## Summary
...

## Confirmed Findings
...

## Current Status
...

## Next Actions
...

## Handover Summary
...

## Evidence Availability
- Partial evidence: monitor:253825030 unavailable (not-found).
```

**Rules**:
- The five required AI-authored sections remain the existing required sections.
- Metadata, provenance, evidence status, and the `## Evidence Availability` section are
  system-authored, deterministic, and never generated by the AI.
- Every AI-authored item contains at least one inline stable evidence identifier.
- The system disclosure is present whenever evidence is partial or has unavailable references.
- The file is written only after evidence, provider, output, and citation validation succeed.

## Projection Contract

`backend/services/investigations.py` detects provenance from `evidence-provenance.json` first,
then `ai-evidence` metadata in `investigation.md`, then legacy files/metadata. The `evidence`
projection is extended as follows:

| Field | Required | Rule |
|-------|----------|------|
| `provenance` | yes | `ai-evidence` for Feature 016 records; legacy values preserved |
| `availability` | yes | `available` for valid `ai-evidence`, `partial` when evidence is partial; legacy behavior preserved |
| `access` | yes | Always `read-only` |
| `reference` | yes | Existing FINAL notebook reference behavior |
| `status` | for `ai-evidence` | `complete` or `partial` |
| `references` | for `ai-evidence` | Sanitized stable-ID map from `evidence-provenance.json` |

Legacy `noc-inv` and `copilot-mcp` projections remain unchanged.

## Lifecycle and Routing Compatibility

The following allowlists MUST accept `ai-evidence` in addition to legacy provenance:

- `backend/services/investigations.py` review, transition, and reject guards;
- `backend/services/assistant.py` investigation route validation;
- `backend/services/assistant_context.py` investigation evidence;
- `backend/services/ai_reports.py` investigation route validation;
- `frontend/js/api.js` assistant investigation route validation.

Error messages and UI labels must use provider-neutral language (for example, "supported
investigation evidence provenance") rather than requiring noc-inv or Copilot MCP.

## UI Display

Investigations UI displays:

- provenance label `AI evidence (Feature 015)` for `ai-evidence`;
- evidence status `COMPLETE` or `PARTIAL`;
- available/unavailable reference counts and bounded unavailable identifiers;
- configured provider label/model;
- the read-only Datadog REST evidence and configured AI provider generation path.

The UI MUST NOT state that noc-inv, Copilot, or Datadog MCP are required for new investigation
generation. Legacy records may retain their legacy provenance label.
